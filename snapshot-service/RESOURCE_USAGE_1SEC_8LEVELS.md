# 1秒間隔・8レベル・4銘柄でのリソース使用量見積もり

## 設定変更

### 現在の設定
- **スナップショット間隔**: 30秒
- **レベル数**: 3（BID/ASK各3レベル）
- **銘柄数**: 4
- **キューサイズ制限**: 500件
- **バッチ書き込み間隔**: 10秒

### 提案する設定
- **スナップショット間隔**: 1秒（30倍の頻度）
- **レベル数**: 8（BID/ASK各8レベル）
- **銘柄数**: 4（変更なし）
- **キューサイズ制限**: 500件（変更なし）
- **バッチ書き込み間隔**: 10秒（変更なし）

## メモリ使用量の計算

### 1スナップショットあたりのメモリ使用量

**PriceLevel構造体**（Rust）:
- `price: f64` = 8 bytes
- `quantity: f64` = 8 bytes
- `side: String` = 約24 bytes（"BID"または"ASK"）
- `level_index: i32` = 4 bytes
- **合計**: 約44 bytes/PriceLevel

**MarketBoardSnapshot構造体**:
- `symbol: String` = 約20 bytes（平均的なシンボル名）
- `timestamp: DateTime<Utc>` = 8 bytes
- `bids: Vec<PriceLevel>` = 8 bytes（Vecのオーバーヘッド）+ (8 levels × 44 bytes) = 360 bytes
- `asks: Vec<PriceLevel>` = 8 bytes（Vecのオーバーヘッド）+ (8 levels × 44 bytes) = 360 bytes
- **合計**: 約748 bytes/スナップショット

### データ生成量

**1秒間隔、8レベル、4銘柄の場合**:
- 1秒あたり: 4スナップショット
- 1分あたり: 240スナップショット
- 1時間あたり: 14,400スナップショット

**キューサイズ500件の場合**:
- メモリ使用量: 500 × 748 bytes = 374 KB
- 10秒間隔で書き込むため、最大10秒分のデータがキューに溜まる
- 10秒 = 40スナップショット（4銘柄 × 10秒）
- **実際のキュー使用量**: 約30 KB（40スナップショット）

### 全体のメモリ使用量

**Rustプロセス**:
- **基本メモリ**: 約10-15 MB（Rustランタイム、依存関係）
- **WebSocket接続**: 約2-3 MB（Bitflyer/GMO接続、バッファ）
- **MarketBoard管理**: 約1-2 MB（4銘柄 × 板データ）
- **スナップショットキュー**: 約0.4 MB（500件制限）
- **PostgreSQL接続プール**: 約1-2 MB（接続5本）
- **その他（ログ、バッファなど）**: 約2-3 MB

**合計**: 約16-25 MB

**安全マージン込み**: 約30-40 MB

## CPU使用量の計算

### 処理頻度の変化

**現在（30秒間隔、3レベル）**:
- スナップショット収集: 1回/30秒 = 0.033回/秒
- 1回あたりの処理: 4銘柄 × 3レベル × 2（BID/ASK） = 24 PriceLevel処理

**提案（1秒間隔、8レベル）**:
- スナップショット収集: 1回/秒 = 1回/秒（30倍）
- 1回あたりの処理: 4銘柄 × 8レベル × 2（BID/ASK） = 64 PriceLevel処理（約2.67倍）

**総処理量**: 30倍 × 2.67倍 = **約80倍**

### CPU使用量の推定

**現在のCPU使用率**（30秒間隔、3レベル）:
- Rustプロセス: 約1-2% CPU（2CPU VPSの場合）

**提案する設定（1秒間隔、8レベル）**:
- **スナップショット収集**: 約30-40% CPU（30倍の頻度）
- **WebSocket処理**: 約2-3% CPU（変わらず）
- **DB書き込み**: 約5-10% CPU（データ量が約2.67倍）
- **その他**: 約2-3% CPU

**合計**: 約40-55% CPU（2CPU VPSの場合）

**2CPU VPSでのCPU使用率**: 約20-28%（2CPU全体に対する割合）

## データベース書き込み量

### 現在（30秒間隔、3レベル）
- 1時間あたり: 480スナップショット（4銘柄 × 120回）
- 1スナップショットあたり: 約3 KB（3レベル × 2）
- **1時間あたりのDB書き込み**: 約1.4 MB

### 提案（1秒間隔、8レベル）
- 1時間あたり: 14,400スナップショット（4銘柄 × 3,600回）
- 1スナップショットあたり: 約0.75 KB（8レベル × 2）
- **1時間あたりのDB書き込み**: 約10.8 MB（約7.7倍）

### バッチ書き込み（10秒間隔）
- 10秒あたり: 40スナップショット
- 1回のバッチ書き込み: 約30 KB
- 1時間あたり: 360回の書き込み

## 推奨設定

### メモリ要件
- **最小**: 50 MB
- **推奨**: 100 MB（安全マージン込み）

### CPU要件
- **2CPU VPS**: 約20-28% CPU使用率（許容範囲内）
- **1CPU VPS**: 約40-55% CPU使用率（高負荷）

### 設定ファイルの変更

`config.toml`:
```toml
[snapshot]
interval_seconds = 1  # 30秒 → 1秒
max_levels = 8        # 3 → 8
queue_size_limit = 500  # 変更なし（10秒分のデータを保持可能）

[postgres_writer]
batch_interval_seconds = 10  # 変更なし
max_batch_size = 50          # 変更なし（10秒で40スナップショットなので十分）
```

## 注意事項

1. **CPU使用率の増加**: 約80倍の処理量になるため、CPU使用率が大幅に増加します
2. **DB書き込み量の増加**: 1時間あたり約10.8 MBの書き込み（現在の約7.7倍）
3. **キューサイズ**: 500件制限は維持（10秒分のデータを保持可能）
4. **メモリ使用量**: 約30-40 MB（許容範囲内）

## 推奨事項

### 2CPU/4GB VPSの場合
- **推奨**: 1秒間隔、8レベルは可能
- **CPU使用率**: 約20-28%（許容範囲内）
- **メモリ使用量**: 約30-40 MB（問題なし）

### 1CPU VPSの場合
- **注意**: CPU使用率が約40-55%と高くなる
- **推奨**: 2秒間隔に延長することを検討

### さらに最適化する場合
- **バッチ書き込み間隔を短縮**: 5秒間隔に変更（CPU使用率は増加するが、レイテンシが削減）
- **キューサイズを増加**: 1000件に変更（より多くのデータをバッファリング可能）
